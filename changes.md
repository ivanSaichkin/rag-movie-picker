# Изменения в бэкенде

## Гостевой поиск

- `GET /api/v1/guest/catalog` отдаёт каталог фильтров без входа. `POST /api/v1/guest/recommendations` принимает текст, фильтры, стратегию и лимит результатов.
- Go принудительно выставляет `disable_llm=true` и `generate_explanations=false`. Поиск доступен гостю, а перевод запроса через LLM, отбор с LLM и генерация пояснений доступны только в авторизованном сценарии.
- Запросы гостя не записываются в историю и не принимают `chat_id` сохранённого чата. Лимит запросов по умолчанию составляет 10 в минуту на IP. Его задаёт `RATE_LIMIT_GUEST_PER_MINUTE`. За обратным прокси без настроенного доверенного адреса клиенты делят квоту прокси.

## Сохранённые чаты

- Миграция `0002_chats` создаёт таблицу `chats` и добавляет `chat_id` к записям `search_history`. Внешний ключ из пары `user_id` и `chat_id` связывает подборку только с чатом того же владельца.
- Первый успешный `POST /api/v1/recommendations` создаёт чат и подборку в одной транзакции. Следующие запросы с полученным `chat_id` продолжают этот чат. Существующий `history_id` сохраняется в контракте.
- `GET /api/v1/chats` возвращает список чатов владельца, `GET /api/v1/chats/{id}` отдаёт сохранённые запросы и ответы от первого к последнему, `DELETE /api/v1/chats/{id}` удаляет чат вместе с подборками. Для чужого чата чтение, продолжение и удаление возвращают `404`.
- Каждая запись старой истории переносится в свой чат с исходным ответом и прежним идентификатором истории. До этой миграции связь между запросами не сохранялась.

## Запуск и проверка

- Для существующей базы примените миграцию перед запуском новой версии API. В Docker Compose это выполняет сервис `migrate`. При ручном развёртывании выполните `go run ./cmd/migrate up` из `backend/`.
- Фронтенд использует новые гостевые маршруты и API чатов. Формат запросов Go к Python RAG и gRPC-контракт остаются прежними.
- Локально прошли тесты Go, `go vet`, `golangci-lint` и интеграционные проверки на PostgreSQL 16. В Chrome проверены гостевой поиск, сохранение нескольких подборок в одном чате, восстановление после перезагрузки и доступ из второго аккаунта. В браузерной проверке использовался тестовый RAG по gRPC.
