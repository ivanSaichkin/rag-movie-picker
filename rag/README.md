# Python RAG сервис

Локальная реализация поиска фильмов: собственный BM25, трансформерные эмбеддинги, Qdrant, RRF и LLM через OpenRouter-совместимый API. Go-бэкенд и подключение фронтенда не входят в этот сервис.

Отдельная [документация по архитектуре RAG](docs/architecture.md): компоненты, хранение данных, алгоритмы и прохождение запроса.

## Установка

Нужны Python 3.12 или 3.13 и uv. Все команды ниже выполняются из каталога `rag`.

```powershell
uv sync --locked --extra embeddings
Copy-Item .env.example .env
```

Не перезаписывайте существующий `.env`. В нём задайте:

```dotenv
QDRANT_PATH=.qdrant
DATASET_PATH="../../TMDB 5000 Movie Dataset/tmdb_5000_movies.csv"
LLM_API_KEY=ваш_ключ
LLM_MODEL=идентификатор_выбранной_модели
```

`QDRANT_PATH` включает embedded Qdrant для локальной работы без Docker. Для отдельного сервера удалите эту настройку и используйте `QDRANT_URL`. Embedded-режим поддерживает поиск и фильтры, но не ускоряющие payload-индексы; для эксплуатации предназначен сервер Qdrant.

Трансформер работает локально на CPU, первая загрузка требует интернета и места для весов. Модель и её revision зафиксированы в конфигурации. `EMBEDDING_LOCAL_ONLY=true` запрещает скачивание и использует только существующий кеш.

## Импорт и запуск

```powershell
uv run --locked --extra embeddings movie-rag import
uv run --locked --extra embeddings movie-rag serve
```

Импорт читает весь CSV, строит оба представления и сохраняет manifest в `.state`. Сам импорт не вызывает LLM. Сервер слушает `127.0.0.1:50051`. Остановка — Ctrl+C.

Существующие коллекции не удаляются. Повторный импорт неизменившегося датасета проверяет индекс без дублирования. Для другого датасета, модели, параметров или восстановления после незавершённого импорта задайте **новые** `QDRANT_COLLECTION` и `INDEX_STATE_DIR`. Старый индекс останется доступен по прежним настройкам.

Импорт и сервер одного индекса используют общий файловый lock: перед импортом сервер нужно остановить. Это локальный одноэкземплярный MVP, не распределённая блокировка. При разных директориях состояния на разных хостах блокировка не защищает общую коллекцию.

Без `LLM_API_KEY`/`LLM_MODEL` сервис запускается, но в hybrid работает через dense fallback и возвращает `retrieval_only` с предупреждениями. Это проверка поиска, а не полноценная генерация. Для BM25-only требуется работающая подготовка английского запроса через LLM.

## Вызов gRPC

Контракт находится в `../proto/rag/v1/rag.proto`; сгенерированные Python- и Go-файлы включены в проект. Запрос можно выполнить встроенным примером:

```powershell
uv run --locked python scripts/query.py "Фантастика про космос" --limit 5
```

Доступны `Recommend`, `GetMovie`, `GetCatalog` и стандартный unary gRPC health `Check`. Потоковый health `Watch` не реализован. Порт без TLS предназначен только для localhost/доверенной внутренней сети, не для публичного доступа.

Ответ содержит `mode`, `strategy_used`, `items` и `warnings`. `items` состоят из `movie` и необязательного `reason`. Неизвестные числовые поля protobuf не устанавливаются. HTTP API и история — ответственность будущего Go-бэкенда.

## Слои и зависимости

- `models.py`, `ports.py` — модели и интерфейсы.
- `embeddings.py` — BM25, TransformerEmbedder и композиция представлений.
- `preprocessing.py`, `indexing.py` — CSV, форматирование, импорт и manifest.
- `storage.py` — адаптер Qdrant.
- `retrieval.py` — независимые ветки поиска и RRF.
- `llm.py`, `service.py` — адаптер провайдера и сценарий RAG.
- `transport.py` — gRPC и преобразование сообщений.
- `cli.py` — сборка зависимостей и управление ресурсами.

`RETRIEVAL_STRATEGY` выбирает `sparse`, `dense` или `hybrid`; в каждом случае индекс содержит оба вектора. Английский запрос используется только для BM25, исходный — для dense. LLM не определяет поля карточек: его ID проверяются относительно кандидатов.

Обработчики gRPC синхронные, работают в ограниченном пуле потоков. Модель общая, её вызовы сериализованы. Дедлайн проверяется между этапами и ограничивает сетевые вызовы; уже запущенный inference PyTorch нельзя принудительно прервать, после его завершения просроченный ответ отбрасывается. У клиента gRPC дедлайн срабатывает независимо.

`LLM_CONTEXT_BYTES` — консервативный бюджет UTF-8 для входа, а не точный подсчёт токенов провайдера. Его и `LLM_MAX_OUTPUT_TOKENS` нужно согласовать с выбранной моделью. При невозможности генерации возвращаются поисковые карточки без объяснений; релевантность такого fallback не гарантирована.

## Проверки

Без тяжёлого эмбеддера:

```powershell
uv sync --locked
uv run --locked ruff check src/movie_rag tests scripts
uv run --locked ruff format --check src/movie_rag tests scripts
uv run --locked pytest
```

Unit-тесты используют fake-эмбеддер и подставной LLM. Интеграционные тесты запускают embedded Qdrant и настоящий gRPC на случайном локальном порту, не требуют Docker, ключа или платных запросов.

Необязательный smoke-test настоящей модели из кеша:

```powershell
uv sync --locked --extra embeddings
$env:RUN_MODEL_TESTS = "1"
uv run --locked --extra embeddings pytest -m model
```

Проверка полного каталога не заменяет оценку качества на размеченных запросах: Precision@k и сравнение стратегий выполняются отдельно.

## Проверки в GitHub Actions

В `.github/workflows` находятся два независимых workflow:

- `rag-ci.yml` — Ruff, тесты на Python 3.12 и 3.13 и сборка пакета. Выполняются unit- и локальные интеграционные тесты с embedded Qdrant и gRPC; тяжёлая модель не устанавливается, тест `model` исключён. Ключ LLM и датасет не нужны.
- `rag-contract.yml` — повторная генерация Python/Go-клиентов, проверка отсутствия изменений относительно коммита, форматирование, `go vet` и Go-тесты с детектором гонок. Версии Go-генераторов совпадают с локальным скриптом.

Проверки запускаются при изменении соответствующих файлов на push в `main`, `development`, `ml_*` и в pull request в `main`/`development`. Также предусмотрен ручной запуск `workflow_dispatch` (интерфейс GitHub требует наличия workflow в default branch). У workflow только права чтения репозитория; они ничего не публикуют и не деплоят.

Это проверки кода и контракта, не проверка качества рекомендаций на полном каталоге или доступности реального LLM API. Из-за фильтров путей workflow может быть пропущен при несвязанных изменениях; учитывайте это при настройке обязательных проверок ветки.

## Обновление protobuf

Генераторы Go устанавливаются в локальный `.tools`, не глобально:

```powershell
$env:GOBIN = Join-Path (Get-Location) ".tools"
go install google.golang.org/protobuf/cmd/protoc-gen-go@v1.36.6
go install google.golang.org/grpc/cmd/protoc-gen-go-grpc@v1.5.1
./scripts/generate-proto.ps1
```

После генерации проверьте Python-тесты и `go test ./...`, `go vet ./...` в `../pkg/ragapi`. Сгенерированные файлы вручную не редактируются. Зависимости Python фиксируются `uv.lock`, Go — `go.mod`/`go.sum`.
