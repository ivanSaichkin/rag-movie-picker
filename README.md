# RAG Movie Picker

Локальное веб-приложение для подбора фильмов по описанию пожеланий пользователя. Поиск выполняется собственной реализацией BM25 по датасету **TMDB 5000 Movie Dataset**, а LLM выбирает подходящие фильмы из найденных и объясняет выбор на русском языке.

## 1. Функциональность и границы MVP

Пользователь вводит запрос, например: «Научная фантастика про космос, желательно с приключениями», указывает количество результатов и при необходимости задаёт фильтры по жанру, году и рейтингу.

Приложение возвращает карточки фильмов: название, год, жанры, рейтинг, исходное описание и объяснение рекомендации. Результатов может быть меньше запрошенного, если подходящих фильмов недостаточно.

- По умолчанию запрашивается **10 фильмов**. Верхняя граница задаётся настройкой `MAX_RESULTS`, начальное значение — **50**; ограничение в пять фильмов отсутствует.
- Подбор учитывает текущий запрос, но не историю просмотров и не профиль пользователя.
- Фильмы берутся только из проиндексированного датасета; LLM не добавляет фильмы из собственных знаний.
- В MVP нет регистрации, отзывов, загрузки файлов через сайт, диалога с памятью, стриминга и отдельного фронтенд-сервера.

## 2. Данные

Источник — `tmdb_5000_movies.csv`. Один фильм является одним поисковым документом: разбиение на чанки не требуется. Основной источник содержания — `overview`, дополнительные — названия, жанры и ключевые слова.

Описания в датасете преимущественно англоязычные. Пользователь может писать по-русски: перед поиском LLM формирует английский поисковый запрос, после поиска — русское объяснение. Исходные названия и описания не переводятся при импорте.

| Поля | Назначение |
| --- | --- |
| `id → movie_id` | Стабильный идентификатор фильма и точки Qdrant |
| `title`, `original_title` | Названия |
| `overview` | Описание сюжета |
| `genres → genre_ids, genres` | Идентификаторы и названия жанров |
| `keywords` | Ключевые слова |
| `release_date → release_date, year` | Дата и год выхода |
| `vote_average → rating`, `vote_count` | Рейтинг и количество голосов |
| `runtime`, `original_language` | Продолжительность и язык |

При импорте JSON-строки в `genres` и `keywords` разбираются как JSON, а не через `eval`. Пустые необязательные значения становятся `null` или пустыми списками. При отсутствии голосов рейтинг считается неизвестным. Строки без корректного ID, названия или непустого описания пропускаются с указанием причины; конфликтующие дубликаты ID считаются ошибкой импорта.

Датасет — фиксированный снимок, а не актуальный каталог: рейтинги и состав фильмов не обновляются автоматически. Права на использование и атрибуция определяются условиями исходного набора.

## 3. Архитектура

**Один Python-процесс приложения + Qdrant + внешний LLM API.** RAG — внутренний класс, не отдельный сетевой сервис. FastAPI одновременно обслуживает API и статические файлы сайта.

```text
Браузер: HTML / CSS / JavaScript
                  |
                HTTP
                  |
               FastAPI
                  |
              RagService
              /        \
     MovieRepository    LLMClient (интерфейс)
        /       \              |
 BM25Encoder   Qdrant     OpenRouterClient → внешний API

CSV → CLI импорта → BM25Encoder + MovieRepository → Qdrant
```

| Компонент | Ответственность |
| --- | --- |
| HTTP-слой FastAPI | Валидация запросов, HTTP-коды, выдача JSON и статики |
| `RagService` | Сценарий подготовки запроса, поиска, генерации и проверки ответа |
| `BM25Encoder` | Токенизация, статистика корпуса, собственный расчёт BM25 и sparse-векторов |
| `MovieRepository` | Поиск, фильтры, чтение и запись фильмов в Qdrant; использует encoder |
| `LLMClient` / `OpenRouterClient` | Независимый интерфейс генерации JSON / адаптер конкретного провайдера |
| CLI импорта | Чтение CSV, нормализация, построение и проверка индекса |
| Веб-интерфейс | Форма запроса, состояния загрузки, карточки и сообщения об ошибках |

HTTP-слой не обращается к Qdrant и LLM напрямую. `RagService` не знает формата CSV и деталей HTTP API провайдера. `BM25Encoder` не зависит от FastAPI, Qdrant и LLM.

Основные контракты:

- `RagService.recommend(request) → RecommendationResponse`.
- `MovieRepository.search(query_en, filters, limit) → list[SearchHit]`, а также `get(movie_id)`, `catalog_info()` и `upsert(movies)`.
- `BM25Encoder.fit(documents)`, `encode_document(text)`, `encode_query(text)`; векторы возвращаются как индексы терминов и их веса.
- `LLMClient.complete_json(messages, schema) → dict`; транспортные ошибки преобразуются в ошибки приложения.

Интерфейсы описываются через Python `Protocol`, зависимости передаются в конструкторы. Клиенты создаются при запуске приложения и закрываются при остановке; сетевые обращения асинхронные. Замена LLM-провайдера требует нового адаптера и конфигурации, но не изменения сценария RAG.

Стек: Python, FastAPI, Pydantic, `qdrant-client`, HTTP-клиент для LLM, обычные HTML/CSS/JavaScript и pytest. **Дополнительная БД не нужна:** карточки хранятся в payload Qdrant, исходный CSV и состояние индекса — локально.

## 4. Собственная реализация BM25

**BM25 реализуется в коде проекта без готовых библиотек поиска.** Не используются `rank_bm25`, FastEmbed, готовая модель `Qdrant/bm25` и автоматический расчёт IDF на стороне Qdrant. Для вычислений достаточно стандартной библиотеки Python: `re`, `collections.Counter`, `math`.

### Подготовка текста и статистики

Поисковый текст: `title + original_title + overview + genres + keywords`. Если названия совпадают, название включается один раз.

Для документов и запросов применяется одинаковая токенизация: нижний регистр и выделение последовательностей `[a-z0-9]+`. В MVP нет стемминга, лемматизации и дополнительных весов полей. Это простая воспроизводимая основа; её ограничения учитываются при оценке поиска.

На всём принятом корпусе вычисляются:

- `N` — число документов; `avgdl` — средняя длина документа в токенах.
- `df(t)` — число документов, содержащих термин; повторения внутри документа не увеличивают `df`.
- `tf(t, d)` — число вхождений термина в документ; `|d|` — длина документа.
- Стабильный словарь `термин → целочисленный индекс`, построенный сортировкой уникальных терминов.

### Формула и хранение

Начальные параметры: `k1 = 1.5`, `b = 0.75`.

```text
idf(t) = ln(1 + (N - df(t) + 0.5) / (df(t) + 0.5))

weight(t, d) =
    tf(t, d) * (k1 + 1)
    / (tf(t, d) + k1 * (1 - b + b * |d| / avgdl))

BM25(q, d) = Σ idf(t) * weight(t, d)
             по уникальным терминам t из запроса q
```

Для каждого фильма код строит sparse-вектор с координатами терминов и значениями `weight(t, d)`. Для запроса — вектор с теми же координатами и значениями `idf(t)`. Их скалярное произведение равно выбранной формуле BM25.

В Qdrant используется именованный sparse-вектор `bm25`, без dense-вектора и без IDF-модификатора. Qdrant хранит индекс, применяет фильтры и возвращает top-k по скалярному произведению; расчёт весов остаётся собственным кодом. Такой способ поиска поддерживается [sparse-индексом Qdrant](https://qdrant.tech/documentation/manage-data/indexing/#sparse-vector-index).

Неизвестные термины запроса игнорируются, повторные термины учитываются один раз. Пустой вектор означает отсутствие результатов. Документы с нулевой оценкой не выдаются. Статистика корпуса не пересчитывается под фильтры пользователя.

## 5. Импорт и состояние индекса

Импорт запускается отдельной CLI-командой до обслуживания запросов и не требует LLM API. Порядок:

1. Прочитать и проверить CSV, нормализовать фильмы, вывести причины пропуска строк.
2. Подготовить тексты, словарь и статистику BM25; пустой корпус считать ошибкой.
3. Создать коллекцию Qdrant с вектором `bm25` и payload-индексами для `genre_ids`, `year`, `rating`.
4. Пакетно записать векторы и payload: поля карточки, поисковый текст и версию индекса.
5. Проверить количество записей и сохранить состояние индекса со статусом `ready`.

Локально сохраняются словарь, `N`, `df`, `avgdl`, параметры BM25 и manifest с контрольной суммой CSV, версией токенизации, именем коллекции, числом документов и статусом `building/ready`. Эти файлы — техническое состояние индекса, не отдельная база фильмов.

Повторный импорт того же набора с той же конфигурацией не создаёт дубликаты. Изменение корпуса, токенизации или параметров BM25 требует **полной пересборки**: статистика и веса документов зависят от всего корпуса. В MVP пересборка выполняется при остановленном приложении; параллельные импорты запрещены.

Приложение обслуживает поиск только при согласованном состоянии manifest, encoder и коллекции. Незавершённый импорт или отсутствующий индекс означает `not ready`, а не пустой каталог.

## 6. Сценарий подбора и работа с LLM

1. FastAPI проверяет запрос, число результатов и фильтры.
2. Первый вызов LLM преобразует пожелания в короткий английский `search_query_en`, сохраняя смысл. Подготовка не должна превращать отрицания в желаемые признаки.
3. Репозиторий кодирует запрос собственным BM25 и ищет кандидатов в Qdrant. Размер пула: `min(размер каталога, max(30, 3 × limit))`; фактически результатов может быть меньше.
4. Если кандидатов нет, приложение сразу возвращает пустой результат без второго вызова LLM.
5. Второй вызов LLM получает исходный запрос, ограничения и карточки кандидатов. Модель возвращает только `movie_id` и краткое `reason` на русском для выбранных фильмов.
6. `RagService` проверяет JSON, допустимость ID, отсутствие повторов и количество результатов. Поля карточек подставляются из репозитория, а не из текста модели.

Фильтры формы применяются в Qdrant **до отбора кандидатов**: несколько жанров означают «любой из выбранных», границы года и минимального рейтинга включаются. Неизвестное значение не проходит соответствующий фильтр. Текстовые пожелания учитываются поиском и LLM; для строгого ограничения по году, жанру и рейтингу используются поля формы.

В LLM передаётся только ограниченный набор карточек, не весь CSV. При превышении бюджета контекста пул сокращается по поисковому рангу с предупреждением `CONTEXT_LIMIT`. Количество выдачи ограничивается запросом, но не дополняется неподходящими фильмами ради достижения заданного числа.

Адаптер LLM отвечает за авторизацию, таймауты, разбор ответа и не более одного повтора при временной ошибке. Провайдер, модель и бюджеты настраиваются. Использование структурированного ответа зависит от возможностей выбранной модели; локальная проверка схемы обязательна в любом случае.

Инструкции внутри запроса и описаний считаются данными, а не командами системе. Модель не вызывает инструменты и не получает секреты. Объяснения должны опираться на переданные сведения; проверка ID защищает состав выдачи, но сама по себе не гарантирует достоверность каждого объяснения.

**Отказы:**

- Ошибка подготовки английского запроса — явная ошибка сервиса; русский запрос не отправляется незаметно в англоязычный BM25.
- Ошибка финальной генерации или невалидный ответ — карточки из top BM25 без объяснений, режим `retrieval_only`.
- Валидный ответ с меньшим числом рекомендаций — обычный результат с предупреждением; валидный пустой список — `empty`.

## 7. HTTP API

| Метод и путь | Назначение |
| --- | --- |
| `GET /`, `GET /static/*` | Страница приложения и статические ресурсы |
| `GET /api/v1/catalog` | Жанры, число фильмов, доступные годы, default/max результатов |
| `POST /api/v1/recommendations` | Подбор фильмов |
| `GET /api/v1/movies/{movie_id}` | Карточка фильма |
| `GET /health`, `GET /ready` | Жив ли процесс / готов ли индекс и доступен ли Qdrant |

Пример запроса:

```json
{
  "query": "Фантастика про космос и приключения",
  "limit": 10,
  "filters": {
    "genre_ids": [878],
    "year_from": 2000,
    "year_to": 2015,
    "min_rating": 6.5
  }
}
```

`query` — непустая строка после удаления крайних пробелов, до 1000 символов. `limit` — целое от 1 до `MAX_RESULTS`, по умолчанию 10. Фильтры необязательны; рейтинг — от 0 до 10, начальный год не больше конечного, ID жанров должны существовать в каталоге. Некорректные значения отклоняются, а не исправляются молча.

Контракт ответа:

| Поле | Содержание |
| --- | --- |
| `mode` | `generated`, `retrieval_only` или `empty` |
| `items` | Массив карточек: `movie_id, title, year, genres, rating, vote_count, overview, reason` |
| `warnings` | Массив объектов `code, message`; пустой при отсутствии предупреждений |

`reason` равен `null` в режиме `retrieval_only`; `items` пуст в режиме `empty`. Возвращается не более `limit` уникальных фильмов. Коды предупреждений: `FEWER_RESULTS`, `NO_MATCHES`, `GENERATION_UNAVAILABLE`, `CONTEXT_LIMIT`.

Успешный поиск, включая пустой результат и fallback, возвращает HTTP 200. Ошибки: 422 — некорректный запрос; 404 — неизвестный фильм; 503 — индекс не готов, Qdrant недоступен или не удалось подготовить запрос; 504 — таймаут подготовки запроса. Тело ошибки: `{"error": {"code": "...", "message": "..."}}`, без ключей и внутренних ответов провайдера.

## 8. Интерфейс и эксплуатация

На странице находятся поле пожеланий, количество результатов, необязательные фильтры и кнопка поиска. Максимум количества берётся из API, а не зашивается в JavaScript. Предусмотрены состояния: ожидание, загрузка, результат, ничего не найдено, ошибка и выдача без объяснений. Во время запроса кнопка отключается.

Карточки показывают исходное описание на английском и объяснение на русском. Неизвестные значения отображаются как «нет данных», а не как ноль. Постеры не обязательны. Пользовательский текст и ответы LLM выводятся как текст, без исполнения HTML.

Приложение и Qdrant доступны только локально. LLM-ключ хранится на сервере, не передаётся в браузер и не попадает в Git или логи. Пользователю сообщается, что запрос и найденные описания передаются внешнему LLM-провайдеру. По умолчанию журналируются этап, длительность, число кандидатов и код ошибки, но не полный запрос или ответ.

Основные настройки:

| Настройка | Назначение |
| --- | --- |
| `QDRANT_URL`, `QDRANT_COLLECTION` | Подключение и коллекция |
| `DATASET_PATH`, `INDEX_STATE_DIR` | Исходный CSV и локальное состояние индекса |
| `BM25_K1=1.5`, `BM25_B=0.75` | Параметры собственной реализации |
| `DEFAULT_RESULTS=10`, `MAX_RESULTS=50` | Размер выдачи; максимум можно увеличить |
| `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` | Провайдер и модель |
| `LLM_TIMEOUT_SECONDS`, `LLM_MAX_CONTEXT_TOKENS`, `LLM_MAX_OUTPUT_TOKENS` | Ограничения ожидания и размера генерации |

Конфигурация проверяется при запуске: `1 ≤ DEFAULT_RESULTS ≤ MAX_RESULTS`, `k1 > 0`, `0 ≤ b ≤ 1`. Бюджеты контекста и ответа согласуются с моделью и желаемым числом рекомендаций; увеличение `MAX_RESULTS` само по себе не расширяет контекст модели.

## 9. Проверка и критерии готовности

Автоматические тесты покрывают:

- **BM25:** ручной расчёт на небольшом корпусе, частоты терминов и документов, нормализацию длины, повторные и неизвестные слова, пустой запрос; совпадение собственной оценки и результата Qdrant с допустимой погрешностью.
- **Импорт:** JSON-поля, пропуски, дубликаты, воспроизводимый словарь, повторный запуск и отказ обслуживания несовместимого индекса.
- **RAG:** фильтры, динамический пул кандидатов, ограничение выдачи, отсутствие результатов, чужие и повторные ID от LLM, невалидный JSON, таймауты и fallback.
- **API и UI:** валидацию, безопасный вывод текста, состояния загрузки и отображение предупреждений.

Качество проверяется на фиксированном наборе минимум из 20 русскоязычных запросов: жанры, темы, ограничения и заведомо отсутствующие совпадения. Для каждого задаются критерии релевантности; оцениваются Precision@k при фиксированном k, соблюдение фильтров и обоснованность объяснений. Если найдено меньше k фильмов, это фиксируется отдельно. BM25-only и итоговая выдача сравниваются на одинаковых запросах; успех не определяется только красотой текста LLM.

**MVP готов, если** CSV воспроизводимо индексируется, сайт выдаёт отобранные из каталога фильмы в запрошенном количестве или явно объясняет недобор, фильтры соблюдаются, BM25 написан самостоятельно, ошибки обрабатываются предсказуемо, а смена LLM-провайдера не затрагивает `RagService`.
